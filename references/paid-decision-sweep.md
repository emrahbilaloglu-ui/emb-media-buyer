# Active paid decision sweep

Use this read-only gate for a campaign or other declared population of paid ads when deciding what to pause, rotate, continue, hold, or review at an existing cadence. A status lookup, benchmark, or ordinary trend review is a different job. Split incompatible currencies, attribution definitions, report time, or platform products into separate sweeps.

## Collect independently, then join

1. Read the full native campaign/set/ad inventory independently of performance and without a spend or purchase filter. Keep configured and effective state, parent and account identity, lifecycle dates, and verified creative/treatment binding. Include paused/historical IDs in the inventory or observed lifecycle union. Read relevant parent budget type, actual concentration, and promotion binding separately.
2. Pull complete ad-ID lifecycle and ad × account-day reports with successful pagination and no top-N limit. Use the same as-of, population, currency, time zone, metric and outcome definition; record attribution window separately from impression/conversion reporting date. An older query with a different attribution setting is a separate view, not a repair to this join.
3. Map one canonical platform count and one compatible value action type. A count alias is not another purchase. A positive count with absent value or wrong/unknown currency is `VALUE_UNVERIFIED`; a verified zero value is different. Keep count/value conflicts explicit. For other platforms supply the equivalent adapter mapping and source evidence. Keep merchant relationships and actual merchant outcomes separate from platform credits; missing binding is not zero orders.
4. Read an independent campaign control, and independent set controls when needed for sparse certification. Record query scope, page completion, source references and retrieval times. Keep an evidenced residual with scope and impact, never distribute it to a missing ad or use equal totals to certify missing IDs or pages. Sparse no-delivery needs verified native parent/ID, complete report scope, sourced sparse behavior and independently matching parent totals. Otherwise leave the missing metrics null and coverage incomplete.

The normalized input has these blocks:

| Block | Minimum contract |
|---|---|
| `scope` | `platform`, `account_id`, `campaign_id`, `currency`, IANA `timezone`, offset `as_of`, `lifecycle_start`, `attribution`, `report_time` |
| `inventory` | independent `manifest`; `ads` with `account_id`, `campaign_id`, `parent_id`, `ad_id`, `configured_status`, `effective_status`, `lifecycle_start`, `epoch_id`, `epoch_started_at` (null if unknown), `binding_verified`; `parents` with matching parent identity and statuses, `currency`, and `daily_budget` when known |
| `lifecycle`, `ad_days` | each has a `manifest` and `rows`; rows have the four IDs, spend, available intent metrics (`impressions`, `lpv`, `atc`, `checkout`), normalized keyed `actions`, `action_values`, `value_currency`, and `date` on daily rows |
| `controls` | independent `manifest`, compatible `totals` (`spend`, `purchases`, `purchase_value` and supported controls), optional exact parent `totals` by `parent_id`; `residual_policy` keyed by metric with scope-specific `absolute_tolerance`, `evidence`, `impact` |

Manifests bind the scope, `source_id`, `retrieved_at`, `complete` and `pagination_complete`. For report/control manifests include `grain` (`ad`, `ad_day`, or `campaign_and_parent`), `start_date`, `end_date`, and `query_scope_evidence`. Report `mapping` carries `count_action_type`, `value_action_type`, `evidence`, optional `count_aliases`, and sourced flags `missing_count_is_zero` and `missing_value_for_zero_count_is_zero`. These flags qualify an observed row, not a missing ad. Only provide `sparse_no_delivery_evidence` when that behavior is verified for the specific query.

## Run and interpret the artifact

```bash
python3 scripts/account_review.py paid-sweep --input normalized-input.json --top 15
```

`--top` changes the visible summary only. Save the full JSON artifact in the existing review's evidence directory. `ok: true` means the command emitted an artifact; read `result.complete_for_decision` for coverage, `result.audit_ready` for the combined coverage/handoff gate, and inspect residuals before using rankings. `active_decision` includes ambiguous native states that need review; a paused historical row cannot silently become a live cut target. Separate paid zero-outcome, positive-outcome (including one/two credits), no exposure, and unresolved lanes. CPA is null without a verified nonzero count; ROAS is null without comparable spend/value. A descriptive ranking is never a cut rule. Active status plus positive observed exposure in a qualified window is not proof of instantaneous serving.

Use lifetime exposure, last seven and three **complete account days**, and today's partial row separately. Show the credited impression/report day and spend on later account days without pretending that is the actual order time. Store the prior frozen read and label backfill/revisions separately from new delivery. A partial-day outcome is counterevidence, not an automatic reason to discard the complete windows. Keep the entire ad-ID exposure after rebind; isolate current treatment only where verified, excluding a mixed boundary day. A binding timestamp is not a first impression.

## Carry decisions and review the batch

Supply `decision_handoff` with `prior_decisions` and `current_decisions`, and any `proposals`, `applications`, `epoch_events`, `rebinds`, `main_retention` and `media_history`. Record account/campaign/parent/ad/epoch/as-of, prior observation, age, changes in spend and separate outcome ledgers, status, reason, source and next decision-changing read. Each `next_review` has `at`, `condition` and `source`. Distinguish proposed, awaiting approval, deferred, rejected, triggered, closed by new evidence, rebind transition, and independently verified application. Reconcile proposals minus applied; every remaining proposal must have an explicit disposition and next review. No `applied` state from a write receipt, name, or unrelated provider state.

Compare material creative/copy/offer/destination changes as treatment epochs; a tag/UTM change can be a measurement epoch. Cosmetic edits do not reset the economic history. Explicitly carry or close an open decision across a verified treatment rebind. Same-media evidence across IDs may inform judgment without copying the previous ID's status, decision or authority.

Assess the whole proposed batch by parent, including the last two ads closed together, a single remaining sibling, and possible concentration. A configured parent budget is nominal, not predicted cash or savings. MAIN retention requires the exact verified promoted source under the existing owner rule; a candidate, same product, or equal hash alone is not retention. For every proposed intervention retain exact IDs/epoch, counterevidence and next review. Execution needs the separate live preflight, current authority and independent read-back; this artifact never grants it.

### Creative test opportunity and sibling rotation

Rankings identify rows to review. Low or absent delivery, age, old weak ratios without an adequate observed opportunity, and a sibling's proposed or verified pause do not establish a test failure. If the action depends on redistribution, keep the recipient's current status and record a dated delivery watch outside the approval list. Carry the recipient and sibling IDs, parent and binding, actual baseline spend and impressions, report availability, and what new delivery or funnel evidence would change the decision. For no or low delivery, distinguish missing rows, observed zero spend, and observed impressions; check whether the parent was quiet or spend concentrated elsewhere. Close a withdrawn proposal explicitly so the next run does not treat it as awaiting approval.

After an independently verified sibling pause, compare actual spend, impressions, traffic/intent and credited outcomes for the same ad and treatment, plus parent concentration, in comparable windows. Exclude a mixed change day when using daily reports and label a partial day separately. Record lag or credit revisions and the cost of stopping versus waiting. Where measurable delivery still has not provided a decision-relevant opportunity, continue delivery monitoring or diagnose the allocation problem. Budget share and elapsed days are not exposure. Do not wait for a sibling read to act on an incumbent whose own sufficiently informative observed results or separately verified issue already justify a reversible recommendation.

## Paid decision packet and cadence

Use the paid-audit contract in references/output-contracts.md and validate the packet against the independently generated sweep artifact. An active paid HOLD must declare its real delivery and carry the same continuation record as WATCH/KEEP when continuing. Record current evidence, prior and incremental spend, separate platform/merchant changes, current rationale, expected information, waiting/stopping cost, and the dated next read and trigger response. Reused filler and purchase-present KEEP do not pass. A met trigger requires an explicit new decision, not a scheduler or a default action.

For creative tests mark `paid_audit.decision_context: creative_test` and validate with `--creative-test` before proposing or executing a cut. Every reduction/rotation must bind its own observed performance, actual post-rotation delivery, or a separately verified non-performance issue. Use only current validated reduction/rotation rows for the approval list; do not export an open delivery watch or an archived proposal as an action. The validator checks scope and observed spend, not whether the observed sample is decision-relevant. Explain the latter from the test design, the owner's operating rule, or sourced qualitative economics; do not invent a common spend, time, or CPA cutoff.

### Build the creative decision plan without defaults

Run `python3 scripts/creative_review_plan.py creative-review-input.json --top 15`. Input pairs `paid_sweep` with `adjudications`: each paid row has an exact account/campaign/parent/ad/epoch, `observed_at`, source and evidence IDs, `cut_assessed`, chosen `disposition`, and the measured `performance_review` described in references/output-contracts.md. Supply current action review or continuation, plus `creative_history` for recurring WATCH. Optional evidence includes `first_proposals` and matching `prior_sweeps`, `manual_pauses`, and `decision_views`. Read script/fixture examples for their exact shape. No judgment entry means unresolved; use `issues` to complete the review. `paid_audit` is a packet projection only when eligible; the full packet still needs strict validation. Re-run when the evidence changes. Never fill unresolved rows with a generic rationale to obtain a green packet.

Review both full lanes: spend with no canonical Purchase, and positive Purchase with poor cumulative CPA/ROAS or sustained cost/empty funnel after credible outcomes. Use lifetime plus comparable closed windows, credit date/value and click-versus-view evidence where available. State why the ad itself had adequate opportunity and what makes stopping too early plausible. Low own opportunity/first partial launch, independently verified MAIN retention, manual PAUSED, proven technical issues and real counterevidence get distinct dispositions. An observation can support a reversible recommendation without proving creative failure; no lane or score issues an automatic cut. Sibling count, potential replacement and whether a set would empty belong in implementation effects after that judgment.

### Decide what another paid WATCH buys

- Record the learning question, exact next read, observable condition, and estimated incremental spend range or sourced exposure bound that would trigger re-decision. Use the existing cadence; a projection is not a provider budget or guaranteed spend. Freeze the old predicate and qualify its results as met, pending, or unknown using current native fields or an independently verified event. Missing metrics are not zeros; a known unmet condition is different from unavailable evidence. Due date or reached exposure bound needs re-decision even without an outcome trigger.
- Do not renew by restating a rationale, setting `pending`, moving the date, or adding “check later”. A first checkout may justify a first limited interval; it is never a veto or an automatic repeat. New material click credit, a verified technical change, or an unresolved mixed treatment boundary can support a new bounded question when bound to this ad, timestamp, window and real economics. An older report-date revision and a placement conjecture are not fresh evidence of a working funnel or measurement fault. Keep historical actual click value and separate merchant relationships; trimming an outlier is sensitivity only. Do not reset lifetime/clean-window exposure when a new credit starts a new post-credit window.
- Show waiting CUTs separately: first proposal and elapsed time, comparable incremental observed spend through the current cut, latest native status, and approval/read-back state. Spend difference is not attributable lost profit or guaranteed savings. Distinguish user manual PAUSED with activity and independent read-back from an open recommendation or provider receipt. Keep independent judgments on genuinely disputed cases and escalate the unresolved choice; do not manufacture consensus or new authorization.
- Replay an earlier decision with only its frozen data, proposal and as-of. Keep later action timestamps, attribution revisions, or delivery in a separate event/review. A mixed hour/day cannot be retrospectively assigned to a pre- or post-intervention interval beyond what the report proves.

At an existing daily review, persist the input/source manifest, immutable as-of sweep, current decision ledger and verified applications; use them as the next read's prior. Generate headings and counts from that same as-of artifact, not another snapshot. A failed overall gate means the review is incomplete. It does not invalidate a separately scoped, independently verified and explicitly approved risk reduction with no related target, parent, binding or authority gap. Do not change existing automation configuration to introduce this gate without authority.
